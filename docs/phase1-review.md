# 1단계 완료 보고 — 두 모드 공통 틀

검증일: 2026-09-27. 범위: 기존 힘의 표현과 평형, 마찰력과 공통 틀·갤러리. 새 단원은 만들지 않았다. 검증 환경은 Windows Chrome와 puppeteer-core 23이며, 실제 스마트폰·스크린리더를 사용한 시험은 별도로 남아 있다.

## 만든 화면과 활동

모형 모드에는 같은 물체·장치와 힘 화살표, 핵심 조건, 정확한 모형값, 재생과 「실제 모습 ↔ 모형」 전환이 있다. 미션·기록·문제를 숨기고, 실험해도 기록이나 미션 증거가 쌓이지 않는다. ‘실제 모습’도 사진이 아니라 장면을 단순하게 그린 그림임을 안내한다.

학습 모드에는 기존 활동과 변인 고르기 미션, 측정 흔들림, 반복 측정, 공통 기록장(표·조건별 평균·축 선택 산점도·CSV), 확인 문제 3개, 가정 5문장, 키보드 조작과 그래프 데이터 표가 있다. 처음 방문할 때 두 카드로 고르고 마지막 선택을 기억한다. 주소와 머리글에서도 모드를 지정한다.

힘의 표현과 평형은 비상교육 중1 p.157–161, [9과05-01]에 대응한다. 미션은 다음 7개다.

1. 마음대로 당겨 보기
2. 화살표로 힘 나타내기(왼쪽 60 N, 끌기 또는 키보드)
3. 50 N과 30 N으로 합력 80 N·20 N 만들기
4. 두 힘 대신 합력 하나로 당기면? (예상 후 자국 비교)
5. 당겨도 꼼짝 않는 상자(1초 이상 평형)
6. 합력과 힘의 평형 정리하기(빈칸 4개 일괄 확인)
7. 힘 ①의 크기만 바꾸어 비교하기(② 크기·두 방향 통제)

마찰력은 p.170–171, [9과05-02]에 대응한다. 미션은 다음 7개다.

1. 살살 당겨 보기
2. 나무 면에서 재기
3. 사포 면으로 바꿔 재기
4. 추를 올리면? (예상 후 추 2개 측정)
5. 마찰력 정리하기(빈칸 3개 일괄 확인)
6. 힘 센서 그래프의 봉우리(중학교 범위 밖임을 명시)
7. 접촉면만 바꾸어 공정하게 비교하기(추 개수·당기는 방법 통제)

두 실험실 모두 진단·적용·새 상황의 선택형 확인 문제 3개를 제공한다. 틀린 선지마다 이유가 있다. 예상의 정답을 고르는 것만으로 실험 미션을 통과하지 않는다. 갤러리의 탐구 경로는 힘의 표현과 평형 → 중력 → 탄성력 → 마찰력 → 부력 → 알짜힘과 운동 상태 변화 순서이며 미구현 4개는 준비 중으로 표시한다. 자체 실험실 두 카드에 모형·학습 링크와 7개 진행 점을 넣었다.

## 계산과 가정

두 모드가 동일한 물리 엔진을 공유한다. 힘 실험은 오른쪽을 +로 두어 F = d₁F₁ + d₂F₂, 질량 5 kg, a = F/5, 고정 DT=1/120초, 평균 속도로 위치를 적분한다. 이는 개발자 검산식이며 학생에게 F=ma를 학습 내용으로 제시하지 않는다. 바닥 마찰·공기 저항·회전을 생략하고 위아래 힘은 평형이라고 밝힌다. 같은 방향의 두 줄은 구별하려고 벌려 그렸지만 같은 작용선으로 계산한다.

마찰 실험은 전체 무게 W=10+10n N, 질량 W/9.8 kg, 고정 DT=1/240초다. 멈췄을 때 마찰력은 −min(당기는 힘, 문턱값), 미끄러질 때는 접촉면별 일정한 값으로 계산한다. 접촉면별 문턱/미끄럼 비례상수는 매끄러운 면 0.25/0.20, 나무 면 0.50/0.40, 사포 면 0.80/0.65이며 실제 재료의 실측값이 아니다. 학생 화면에는 계수를 내지 않는다. 문턱에 닿는 순간 미끄러짐이 시작되는 모형이다. 힘을 크게 뛰어넘겨 당기면 문턱값으로 잘못 기록하지 않고 다시 재도록 안내한다.

자동 당기기는 3 N/s로 힘을 올린 뒤 속력이 0.2 m/s에 가까워지도록 당기는 힘을 조절한다. 놓으면 마찰 때문에 느려지고 멈추며, 음의 속도로 뒤집히지 않게 한다. 마찰 종류의 이름은 기본적으로 꺼져 있고 범위 밖 미션에서만 다룬다.

흔들림은 힘 센서 각각 ±0.2 N, 마찰 센서 ±0.08 N의 독립 균등 오차다. 0 N 영점은 고정한다. 측정 합력은 반올림한 두 센서값의 부호 있는 합이다. 모형값·화살표 길이·물리 운동·미션 물리 판정에는 무작위 오차를 넣지 않는다. 평균은 같은 조건끼리만 구하고, 평균에도 오차가 남는다고 안내한다. 마찰의 과거 기록은 당기는 방법을 알 수 없어 ‘이전 기록(방법 미상)’으로 분리한다.

## 창의 장치와 한계

- 힘의 표현: 기존 0.5초 자국을 켜서 두 힘과 합력 하나의 움직임을 겹쳐 비교한다. 같은 시간에 같은 위치가 찍히는 효과를 직접 확인한다. 회전·마찰이 없는 나란한 힘 모형의 범위에서 성립하며 합력은 세 번째로 더해지는 힘이 아니다.
- 마찰력: 흔들리지 않는 힘 모형과 재측정 산점도·조건별 평균표를 비교한다. 같은 조건의 측정도 조금 다를 수 있음을 보고, 조건 변경 효과와 측정 오차를 구별한다. 실제 재료의 모든 특성이나 체계적 오차를 재현하지 않으며 평균이 반드시 참값을 주는 것도 아니다.
- 새로운 사물 비유는 넣지 않았다. 보조 층을 꺼도 물체와 힘 모형은 유지된다.

## 손계산 대조

오른쪽을 +로 둔다. 모형/학습 양쪽에서 힘 실험의 수치가 같았고 아래 오차는 10⁻⁸ 이하이다.

| 조건 | 손계산 | 엔진 결과 |
|---|---|---|
| 50 N → + 30 N →, 0.5초 | F=80 N, v=8 m/s, x=2 m | 80, 8.00000000000001, 2.000000000000001 |
| 50 N → + 30 N ←, 0.5초 | F=20 N, v=2 m/s, x=0.5 m | 20, 2.000000000000003, 0.5000000000000002 |
| 50 N ← + 30 N →, 0.5초 | F=−20 N, v=−2 m/s, x=−0.5 m | −20, −2.000000000000003, −0.5000000000000002 |
| 40 N → + 40 N ← | F=0, v=0, x=0 | 모두 0 |
| 두 힘 모두 0 | F=0, v=0, x=0 | 모두 0 |
| 합력 20 N, 0.5초/1초 자국 | x=0.5 / 2 m | 0.499999999999999 / 2.000000000000004 |
| 합력 200 N | v=10 m/s가 되는 0.25초에 관찰 정지 | v=10, t=0.24999999999999997 |

마찰의 3개 접촉면 × 4개 무게를 모두 검사했다. 아래 칸은 ‘움직이기 시작하는 힘 / 미끄러질 때 힘’이며 손계산과 엔진 값이 일치했다(N).

| 접촉면 | 10 N | 20 N | 30 N | 40 N |
|---|---:|---:|---:|---:|
| 매끄러운 면 | 2.5 / 2 | 5 / 4 | 7.5 / 6 | 10 / 8 |
| 나무 면 | 5 / 4 | 10 / 8 | 15 / 12 | 20 / 16 |
| 사포 면 | 8 / 6.5 | 16 / 13 | 24 / 19.5 | 32 / 26 |

각 문턱보다 0.5 N 작게 당기면 v=0이며 마찰력은 당기는 힘과 같은 크기·반대 방향이었다. 문턱에서는 미끄러짐이 시작되고 모든 측정 기록이 설정한 ±0.08 N 범위에 들었다. 당기는 힘을 0으로 줄인 뒤 v=0, 마찰력=0, 역주행 없음도 확인했다.

나무 면·추 2개 자동 당기기의 문턱은 15 N, 안정된 당기는 힘은 12.000001086 N, 속력은 0.199999929 m/s로 손계산의 12 N, 0.2 m/s에 수렴했다. 사포 면·전체 무게 40 N의 같은 실험에서 두 모드의 위치·속도·시간이 완전히 같았다.

결정적 오차 샘플 9.8·9.9·10.0·10.1·10.2 N의 평균 10 N, 영점 0 N, 모형 모드의 정확한 10 N 반환을 검사했다. 기록장의 평균은 실제 저장된 행으로 다시 산술 계산해 대조했다. 일반 무작위 측정 평균이 언제나 10 N이라는 뜻은 아니다.

## 자동 검증과 화면

- `tests/phase1.cjs`: 12개 검증 묶음 통과. 실제 마우스 끌기·클릭·키보드로 각 7/7 미션, 모든 확인 문제의 오답 피드백과 정답 확인, 예측 잠금, 기록·평균·음수 CSV, 새로고침 복원·다시 하기, 잘못 통제한 설계 거절, 과거 데이터 이관, 모형 모드 기록 차단을 검사했다.
- `tests/phase1-edge.cjs`: 8개 확인 항목 통과. 모바일 키보드 미션 서랍, 가정 창의 Esc와 포커스 복귀, 그래프 6점과 표 6행 일치, 축 변경, 최대 힘 화살표 범위, 마찰 운동의 모드 동등성, 시간 그래프의 전체 데이터 표, 갤러리 2/7 진행 표시를 검사했다.
- 인계 `fbv2.mjs`: 기존 힘 미션 6/6, 끌기로 왼쪽 60 N, 콘솔 오류 0.
- 인계 `frtest2.mjs`: 기존 마찰 미션 6/6, 마우스 길게 누르기, 큰 힘 건너뛰기 거절, 조건 변경 시 F=0, 콘솔 오류 0.
- 인계 `kitcheck.mjs`: 두 실험실×두 모드×4화면에서 정상 캔버스, 문서 가로 스크롤 0, 콘솔 오류 0.
- 최종 화면 검사는 1920×1080·1366×768·1024×768·390×844에서 다시 수행했다. 기본 화면 16장, 갤러리 4장 및 기록장·가정·변인·최대 힘 등의 추가 화면을 별도 산출물에 저장했다. 모바일 기록장 내부의 가로 이동은 글자를 읽기 위한 의도된 동작이며 문서 가로 스크롤은 없다.

산출물 이름은 `<실험실>-<model|learn>-<폭>x<높이>.png`이다. `validation.json`, `validation-filtered.json`, `edge-validation.json`에 검사 결과가 있고 `legacy/`에 인계 스크립트 로그와 화면이 있다. 의존성과 테스트용 이미지는 저장소에 추가하지 않는다.

남은 범위: 교사의 수업 적합성 확인, 실제 터치 기기와 스크린리더 사용성 확인. 새로운 단원이나 배포는 이번 단계에 포함하지 않는다. 모델 한계(비례상수·측정 오차를 단순화함, 회전·공기 저항 생략)는 화면에 공개했다. 현재 자동 검증에서 남은 실패 항목은 없다.
